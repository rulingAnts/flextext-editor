### A2. `check-release-integrity.sh` is path-based, so only `rulingants.github.io` exercises it

Worth recording because it is a trap. The script takes `FLEXTEXT_BASE` and fetches
`$BASE/flextext-editor/sw.js`, `$BASE/text-recorder/sw.js` and so on — the **path-based GitHub Pages
layout**. The Cloudflare estate is **host-based** (`app.flextext.app/sw.js`). So pointing it at a
Cloudflare origin produces a confusing false failure:

```
FAILED — a satellite may be serving the wrong engine.
  FAIL: could not read the live editor version (site down, or sw.js changed shape)
```

…because it was looking for `app.flextext.app/flextext-editor/sw.js`, which does not exist by
design. The script's two surviving invariants are both explicitly about the frozen Pages mirrors,
i.e. where existing field users already stand, so `rulingants.github.io` is the host it needs and
the default `BASE` is already correct. **Do not "fix" this by pointing it at Cloudflare.**

(Also noted and discarded: the script appears to exit 0 on failure when piped through `tail`. It does
not — that is `tail`'s exit code. The script's `exit $fail` is sound.)

### A3. Signed-in testing needs no Google credential — a local worker runs in the sandbox

Measured, not assumed: `wrangler dev --local` boots a full Worker with a working local D1 **inside
the sandbox container**, with no Cloudflare account and no network. A probe worker created a table,
inserted and read back a row (`{"k":"local-d1-works"}`). The only proxy denials were Cloudflare's
telemetry hosts (`sparrow.cloudflare.com`, `workers.cloudflare.com`), which block nothing.

The pieces for a credential-free signed-in rig therefore already exist:

- `worker/schema-current.sql` is the full current D1 schema.
- `worker/.dev.vars.example` documents the dev values, and the two it names are deliberately public
  (Cloudflare's always-pass Turnstile **test** keys, and `DEFAULT_RELAY_TOKEN`, the public read token
  already shipped in every client).
- `[env.staging]` in `worker/wrangler.toml` already has its own Worker name, its own D1
  (`flextext-connectivity-staging`), and an `ALLOWED_ORIGINS` that **deliberately excludes every
  production origin** — so a staging client reaching the production backend still fails loudly.

**Recommendation: build issue #116 (`DEV_STUBS`) rather than minting a Google refresh token.** A
synthetic researcher row needs no Google account, no token, and no expiry, and it adds nothing to the
production Worker. It also helps every outside contributor, which is the fork-and-run goal already in
`plans/`.

**Why not a dev route hard-coded to a throwaway Google account**, which was considered:

- The Worker stores a **refresh token** (`drive_refresh_enc`), not a password, so "hard-coded to an
  account" still requires minting and holding a refresh token — it inherits the expiry problem
  rather than escaping it.
- Google refresh tokens expire in **7 days** whenever the OAuth consent screen is in *Testing*
  status. Only *In production* gives long-lived tokens. (The requested scopes — `openid email
  profile` + `drive.file` — are all non-sensitive, so *In production* needs no Google verification
  review. Worth confirming on the Audience page; it is probably already published, since real
  researchers sign in through this client.)
- A session-minting endpoint would live in the Worker that **has no staged rollout** — one
  production version serves every device and every panel at once. If it were ever built it belongs
  in `[env.staging]` only, never the production Worker.

**And no credential could have opened the hosts anyway.** The egress block is enforced by the sandbox
proxy before any credential is consulted; a token is something a host checks once you reach it. The
allow-list was the only thing that could work, which is what happened.

### A4. The beta estate has never been deployed — `beta.flextext.app` is not a network block

`beta.flextext.app` and `beta-record.flextext.app` return `000` from the sandbox, which looks
identical to a blocked host but is not one. The proxy distinguishes them:

| | gateway answer to CONNECT | means |
|---|---|---|
| a genuinely blocked host (e.g. `mcp.slack.com`) | **403** | policy denial |
| `beta.flextext.app`, `beta-record.flextext.app` | **502** | permitted by policy, **upstream unreachable** |

So the beta hostnames are already allowed as `flextext.app` subdomains. They fail because nothing is
serving them. Confirmed from the other side: the workers.dev twins answer **404**, which is
Cloudflare's edge replying for a Worker that does not exist:

```
flextext-editor-beta.68mh29kgsd.workers.dev     404
flextext-recorder-beta.68mh29kgsd.workers.dev   404
```

This matches CLAUDE.md exactly: *"The first beta deploy creates the seven `<worker>-beta` Workers by
itself (`wrangler deploy --name`); their custom domains are attached once in the dashboard
afterwards."* **That first deploy has not happened.** Branch state:

- `origin/beta` is at `2f9d1da` (v716) — the same commit as `productionWeb`, so **0 commits are
  soaking**.
- `origin/beta..origin/main` is **2 commits**, both docs-only, so the branches have not meaningfully
  diverged.

**Nothing is broken and nothing needs unblocking.** But a release planned around beta should expect
the first "Deploy to beta" to also be the run that mints the Workers, after which the seven custom
domains need attaching once by hand — and only then can an agent verify a beta deploy.

⚠ **General lesson, since this one nearly went into the report backwards:** `000` from the sandbox
means "no HTTP response", which covers both "policy refused you" and "nothing is there". Read
`$HTTPS_PROXY/__agentproxy/status` for the gateway's own code — 403 and 502 are different diagnoses
with different fixes — before reporting a host as blocked.

### B0. What a reviewer should know first

Two findings were worth the whole exercise:

**A gap line inherited guessed boundaries and exported them as measured times.** `isPlaced` is
`isAligned && !isPlaceholder`, and an **estimate satisfies both** — so a gap row is offered between
two estimated lines, and its own edges are then those neighbours' interpolated values. Written with
no `guess`, the export contradicted itself at the same millisecond: the neighbour wrote
`~0:05.000`, the new line wrote `0:05.000` with no `~` and no instruction entry; the EAFs published
the interpolation as an alignment with no marking at all. **This is the precise failure v717 was
built to prevent**, reintroduced one release later by a reasonable-sounding comment — the code said
the gap's edges "are as real as the times that produced them", which is true only when those edges
are real, and nothing tested that. Fixed by inheriting per edge through `edgeGuessed`, marking
`estSource: 'edit'`, and leaving 0 and D alone because they are facts rather than interpolations.

**Case 16's protection was switched off wherever gaps actually ship.** `checkAlignmentPending()`
short-circuited on `!timingBannerOn()`. But `gapLines` and `timingBanner` are *independent*
researcher checkboxes, so "gaps on, banner off" is the **default** on every paired device — and
`timingBannerOn()` is only true there once the researcher ticks it. So the guard that stops a
coworker retyping a sentence into a hole caused by a wrong file worked only on unpaired devices.
With the banner off the coworker gets **no warning of any kind**, which makes hiding Add more
necessary, not less. The existing test stubbed `timingBannerOn → true`, so the false branch had
never run.
