## 2. What Phase C is, in two paragraphs

An owner researcher (Seth) can invite another researcher into one of their **projects** (his estate
has two: *Fayu Text Corpus*, *Dani Dictionary*). Increment 1 joined the two things previously both
called "a project" — a D1 `project` row and a Google Drive folder — via `project.drive_folder_id`.
Increment 2 is the authorization: who may do what to whose devices and texts.

**Access is PROJECT-scoped** (Seth, 2026-08-20). A member reaches everything in their project and
nothing outside it — not another project, and **not the account root folder**. Finer separation is a
separate project, which is the mechanism his estate already uses. There is deliberately **no
per-device visibility list**; one was built and removed the same night because Drive is addressed by
file id and could not honour it, so it would have been a checkbox that claimed to hide a device it
did not hide.

## 3. Architecture you need before changing anything

**`authMember(req, env, target, needCap)` in `worker/src/v1.js` is the single authority (I1).**

```
returns  null            → not authenticated at all      → route answers 401
         { ok: false }   → authenticated, not authorized → route answers not_found
         { ok: true, caller, owner, project_id, caps, isOwner, legacy? }
```

Every call site is:
```js
const ctx = await authMember(request, env, { instance: instanceId }, 'manageDevices');
if (!ctx)     return j({ error: 'unauthorized' }, 401, origin, env);
if (!ctx.ok)  return j({ error: 'not_found' },    404, origin, env);
const r = ctx.owner;   // ← the PROJECT OWNER's row. Drive acts in THEIR account.
```

⚠ **`ctx.owner` and `ctx.caller` are different on purpose.** `owner` is whose Drive/credentials the
work runs against; `caller` is who is acting, and is what audit logging and `wrapped_by` must use.
They are identical for an owner, which is exactly why conflating them would pass every test today
and mis-attribute every member action the day sharing ships.

**Non-negotiable invariants** (each has a test and/or a containment check):
- **I1** — authMember is the only place authorization is decided.
- **I4 fail closed** — every unresolvable step denies. Never fall back to `researcher_id` scoping.
- **Denial is indistinguishable from absence.** `not_found`, never `403`, or ids become enumerable.
- **The owner is never a `project_member` row.** Ownership is `project.owner_id`.
- **Wrap-to-owner** — the owner always retains a readable copy of every device key.
- **Identity is not advertised** — no email or display name in cross-researcher lookups.
- **wipe / force-remove / key delivery are owner-only.** No capability delegates them.

**The dual-read window.** `instance.project_id` is filled lazily. When it is NULL, the instance's own
`researcher_id` gets owner-equivalent access. ⚠ This branch **must never consult `project_member`** —
that is what keeps it from being a widening fall-through. Removing it as an experiment fails the
device-compat probe with 20 assertions: no device can be claimed or approved at all.

## 4. What v1 members actually get: DEVICE MANAGEMENT

| capability | grantable in v1? |
|---|---|
| `manageDevices` | ✅ rename, settings/commands, revoke, install approve/revoke |
| `createInvites` | ✅ invite a coworker to enrol a device |
| `cancelOthers` | ✅ (currently grants nothing extra — the cancel route has no issuer check) |
| `assignTexts` | ❌ **refused** on both write and read paths |
| `drive` | ❌ **refused** on both write and read paths |

⚠ **The nine same-root findings were closed by making those two capabilities UNGRANTABLE, not by
repairing the routes.** The account-wide `docId` Drive searches are still there, untouched. The Drive
lane is **deferred, not fixed.** Do not read the passing tests as evidence those routes are safe.

**To re-enable:** remove the name from `DEFERRED_CAPS` (one module-level list, consulted by both
`validateCaps` and `authMember`) — but only after the Drive scoping exists (§5, item 0).

Other gates that are load-bearing and easy to undo by accident:
- **Text-scoped commands** (`assign`, `delete`, `uploadDelete`, `setDone`) require `assignTexts`, not
  merely `manageDevices`. `delete` destroys a field worker's transcription.
- **`changeSettings` must carry `enc`.** A plaintext payload is refused. Settings are E2EE so the
  worker *cannot* allow-list keys — the real guard is device-side (`REMOTE_FORBIDDEN` in `app.js`),
  which refuses `relayWorker` from a pushed patch.
- **Sharing is refused until the owner has migrated** to Drive project folders (`not_migrated`, 409).

1. **`GET /v1/researcher/keys` has no membership, project or revoked predicate.** It is the only way

3. **`POST /v1/researcher/delete` deletes no `project`, `project_member`, `member_key` or `session`
   rows.** Retention, not access — belongs with the revoked-row minimisation work.
4. **`authMember`'s `{ crowd }` target has zero call sites.** Every crowd route is still
   `WHERE researcher_id=?`; the containment script never scans `/v1/crowd`.
5. ⚠ **A member-enrolled device shows the field user the OWNER's identity**, because it resolves
   through `instance.researcher_id`. The entire purpose of that gate is that the person being linked
   can tell who is linking them. This is a **correctness bug in the anti-phishing gate**, not a
   vulnerability — and it is the one to read first.
6. **No attribution logging for member device actions** (rename, revoke, approve, key, invite).

## 8. Traps that already bit, in this codebase

1. **The enumerated rebuild** (`researcher.js` `listView`) — a server field is invisible to the panel
   unless it is named there. Has silently eaten a field four times.
2. **`viewSig`** (`researcher-panel.js`) — anything rendered that is not in the signature never
   repaints. This is the whole explanation for "the panel doesn't update".
3. **A guard that greps for one spelling.** `check-project-scoping.sh` reported "no route uses
   authResearcher" while one did, because it matched `const r = await authResearcher` and the route
   read `asResearcher = await authResearcher`. **A guard that passes over the thing it guards is
   worse than none — it gets quoted as evidence.**
4. **A guard that checks a mechanism exists but not that it acts.** The TEXT_COMMANDS check passed
   with the list emptied.
5. **A test that pins literal source text** breaks when the behaviour it names is *improved*, which
   trains people to edit assertions without reading them. Happened twice.
6. **`notes/` is gitignored** — anything you want to keep goes in `plans/` and gets committed.
7. **Python slice edits**: bounding a replacement with an end-anchor that can appear *before* the
   start anchor yields an empty slice, and `str.replace('', new)` inserts between every character.
   This produced a **459 MB** `BACKLOG.md`; GitHub's push limit was the only thing that caught it.
   Assert the slice length.

## 9. Settled decisions — do not re-litigate

- **Drive access is per-project.** Seth: *"per project is good enough."* Finer = a separate project.
- **A member must not reach the account root folder**, not merely other projects — so a member's
  file listing must be **rooted at their project folder**, never walked from master and filtered.
- **No sharing until the owner has migrated** to project folders — on a flat estate there is no
  subtree to confine a member to.
- **Per-project "Unassigned" is REQUIRED**, not tidiness: an account-level one sits outside every
  project, so a member would watch finished texts vanish as they were swept.
- **The Drive checkbox does NOT ship in the sharing UI** — absent, not greyed out.
- **Revoked devices: the server forgets, Drive remembers.** Attribution is ethically required in
  language documentation. Drive organisation is *sweep texts to Unassigned → then move the emptied
  device folder into "Revoked"*; the order is the design (see `BACKLOG.md` for why).
- **Cross-project text moves** are a wanted future feature: two grant resolutions, and the capability
  is *directional* (transfer OUT).
- **Recursive projects**: filed, not built. Nothing forecloses it.
- **Browser support is Chromium only.** Safari/iOS is out of scope, not a gap.
