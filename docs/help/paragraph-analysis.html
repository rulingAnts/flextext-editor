The Paragraph Analysis Tool

A tool for grouping the lines of a text into a hierarchy — which line supports which, and how — and drawing the result as a semantic structure diagram. It reads and writes its own .fxpa file and never alters your language data.

What this tool is for

Discourse analysis asks how the parts of a text hold together: which sentence sets the scene, which one carries the main event, which merely elaborates. This tool lets you build that structure over a text you already have, and produce a diagram of it.

It is built around Semantic Structure Analysis (SSA), but it does not force SSA on you. The labels are free text, so Longacre-style plot structure, Beekman–Callow relations, or your own scheme all work. The tool enforces only structural rules — the ones that keep a hierarchy a hierarchy. Everything semantic is yours.

It never edits your text. Grouping is metadata. The baseline, words, glosses and free translations you imported are not touched by any grouping operation, and no grouping operation can merge or split a line or an audio segment. If you need to split or join lines, do it in the FlexText editor or ELAN and re-import.

Getting a text in

Three ways to start:

  • Open a .fxpa file — an analysis you or a colleague saved before.
  • Import a text — a .flextext from FLEx, or an ELAN .eaf. Each phrase becomes a line you can group.
  • Start a blank chart — type propositions directly, with no source text. Use this when you are analysing meaning rather than an existing recording.

Every document is validated as it opens (see Safety). If the file has problems the tool can fix without inventing anything, it repairs them and tells you what it did.

Selecting and grouping

Click a line, or a group heading, to select it. To select a run of them:

Shift-click, Ctrl-click or Cmd-click at the other end of the run. Any of the three works.

This needs a keyboard. A touchscreen has no modifier key, so selecting a run is not currently possible by touch alone — group the units you can reach, then use Extend in the Edit group dialog to move its boundary one unit at a time.

The selection always stretches from where you started, so it is always a single unbroken run. You cannot select line 2 and line 7 without lines 3–6.

Why runs only. A group is a constituent — a stretch of text that behaves as a unit. A "group" of non-adjacent lines would not be a constituent of anything, and every diagram convention for drawing it would be a lie about the structure. The restriction is what makes the diagram trustworthy.

Three ways to run a command: the toolbar, right-click on a unit, or the keyboard — ⌘G / Ctrl+G to group (or edit the selected group) and ⌘U / Ctrl+U to ungroup. Right-clicking a unit that is not already selected selects it first, so the menu always acts on what you can see. Shortcuts are ignored while you are typing.

With a run selected, press Group. The dialog lets you set the relation, the discourse slot, each member's role, and which members are heads.

Editing a group you already made

Select just its heading, then:

  • Edit group — change labels, roles, heads. This is the same button as Group: with one group heading selected it renames itself, because the two can never apply at once.
  • Ungroup — dissolve it. Its members return to the level above, in place. Nothing is deleted.

Adjusting a group's edges

In the Edit group dialog, Extend and Release move the group's boundaries one unit at a time:

  • Extend absorbs the adjacent sibling above or below. The newcomer arrives plain — no role, not a head — because the tool will not guess what it is to you.
  • Release pushes the first or last member back out, beside the group.

This exists so you can fix a boundary without dismantling the group and rebuilding it. If releasing would leave the group with one member, the group dissolves — a group of one is not a group, and the tool says so before it happens.

Nesting

Groups can contain groups, to any depth. You can work top-down (group everything, then subdivide) or bottom-up (group small units, then group the groups). You never have to dismantle a hierarchy to change part of it.

Heads: what is prominent

In the Group dialog, each member has a HEAD checkbox, unchecked by default.

  • No heads ticked — a symmetrical group. The members are equals (a list, a sequence, a paraphrase pair). Drawn with a dashed spine.
  • One or more ticked — an asymmetrical group. The head is what the group is really asserting; the others support it. Drawn with a solid spine, and the incoming line enters at the head.

Symmetrical versus asymmetrical is derived from whether any head is ticked. There is no separate switch to get out of step with reality.

More than one head

A group may have several heads — two events of equal weight inside one unit, for example. The diagram enters at the average position of the heads, so the line visibly serves all of them rather than picking one.

Known limit. With heads that are not adjacent — say the first and last member — the average lands on a supporting member between them, so the line appears to point at a non-head. It is arithmetically correct and was accepted deliberately. If it reads wrong in a real analysis, say so and it can be revisited.

The three labels: relation, role, discourse slot

A group can carry three different labels. They are deliberately separate fields, because they answer different questions and you often want more than one at a time.

LabelQuestion it answersExample
Relation
(on the group)		 How do this group's members relate to each other? grounds–CONCLUSION, orienter–CONTENT, addition
Role
(on each member)		 What is this member to the group? grounds, CONCLUSION, setting
Discourse slot
(on the group)		 What part does this group play in the whole text? Stage setting, Episode 1, Peak

A group commonly has all three: an Episode 1 that is internally orienter–CONTENT, whose members are orienter and CONTENT. Merging them into one field would force you to choose between an SSA relation and Longacre-style plot structure — so they stay separate.

Roles belong to the group, not the unit: a role is held relative to one relation. The same line in a different group would have a different role.

Labels are optional

None of the three is required. A group with no label of its own is named in the interface by the roles of its members, then by its slot, then by its summary — see the path. That naming is for the interface only; the diagram shows what you wrote and nothing else.

Capitalisation is normalised

The SSA convention writes the prominent member's role in CAPITALS and a supporting member's in lower case. The tool enforces this when the label is stored, so what you see on screen, what goes in the diagram, and what is written to the file always agree. Type in whatever case you like; ticking or unticking HEAD re-cases the role to match.

Propositions

A line of language data says one thing on the surface but may express several propositions. Add them with the + at the end of the line, on the right. It stays faint until you hover or select the line, so it does not compete with the words. Press Enter in a proposition box to add another, Backspace in an empty one to remove it.

Propositions are additions beside the line, never edits to it — which is why they are offered on imported texts. They can be grouped, given roles and made heads, exactly like lines.

Implied propositions

Mark a proposition implied when it is not stated on the surface but is needed for the argument. Implied propositions are shown in brackets, the SSA convention. Whether the brackets are drawn is a setting.

What happens to the line itself

Once a line has propositions with text in them, the propositions stand in the analysis in place of the line. The line still appears in the diagram, greyed and unconnected, at its own position among its propositions — so you can read the restatement against the sentence it restates. Turn this off with Show language-data lines that are not in the tree to get a propositions-only diagram.

An empty proposition box never replaces its line — it is a box you have opened and not yet typed into.

Collapsing — how you get the big picture

Click the ▾ / ▸ caret on a group heading to collapse or expand it. Collapse all and Expand all work on the whole document or on a selection.

Collapsing is the summarising mechanism. A collapsed group is one node in the exported diagram, however much is inside it. So the way to produce a big-picture chart of a long text is: collapse the groups you want summarised, then export.

The export offers two ways to draw a collapsed group:

  • All its lines, inside one bracket (default) — every line still shows, with one bracket around the whole run, no internal structure, no member roles. Same job as the triangle in a generative syntax tree: highlight the larger constituent, ignore the detail below it.
  • One summary line — the group becomes a single row of summary text and the rest is hidden. Densest, and a bigger claim to make on your behalf, which is why it is not the default.

Writing your own summary

By default a collapsed group is summarised by its head's text — a reasonable guess, but a line lifted out of context often makes a poor sentence. The Group dialog has an optional Summary field: whatever you write there is used wherever the group appears collapsed, both in the editor and in the "One summary line" chart option. Leave it blank and the head's own text is used.

Finding your way in a long text

A deep analysis outgrows the screen quickly. The path exists for that.

The two breadcrumb bars

There are two, and they answer different questions. Each has its own switch under View.

BarAnswersShows when
Selected:What have I selected? Something is selected. Carries a ✕ to deselect.
Currently visible:Where am I looking? You have scrolled past the first group heading. Follows the scroll, not the selection.

Both show as much of the hierarchy as fits the width. When a path is too long the middle is elided — the two ends orient you, the steps between are what can be spared.

Clicking a step

With something selected, a single line under the toolbar shows where it sits: Whole narrative › Episode 1 › orienter–CONTENT. Each step is a button.

  • Click a step — go there. It becomes the selection and scrolls into view.
  • Click it a second time — focus that level. The group's own sub-groups collapse, and so does everything beside it, leaving just that level open. Undo restores it.
Two separate clicks — a double-click will not do it. The first click changes the selection, and the path is redrawn around it: the path now ends at the group you picked, the steps after it disappear, and the … may appear or vanish as the path gets shorter. So the step you clicked is usually somewhere else a moment later. Click once, look at where the step has moved to, then click it there. This is also why the second click has no time limit — take as long as you like.

It stays one line however deep the analysis goes. When the path is too long the middle is elided (Whole narrative › … › grounds–CONCLUSION) — the root and where you are now are what orient you; the steps between are the ones you can afford to lose.

The path only appears when something is selected: it is a path to something, so with an empty selection it would just cost a row. Turn it off entirely with View → Show the path.

What each step is called. A step shows the group's own label. If it has none, it shows one worked out from its members' roles — grounds-CONCLUSION — with repeats collapsed, so three coordinate members read conjoining rather than conjoining-conjoining-conjoining, and a numbered series reads stepN rather than step1-step2. Failing that it uses the discourse slot, then the summary, and only then unnamed (G4). These derived names are for the interface only — the diagram always shows exactly what you wrote, and nothing else.

Audio, blank lines and speakers

If the text came from a recording, each line keeps its time span and gets a play button. Grouping never merges or moves audio: a group simply spans its members' time.

Blank lines — gaps between annotated speech, common in ELAN exports and FLEx texts — are real timed spans and stay in the document. Hide blank lines keeps them out of sight, and they are skipped in the diagram, but they are never deleted.

Speakers are carried on the line and shown beside it in the diagram, so a multi-speaker text stays readable.

Safety: what the tool refuses to do

An analysis represents work that can take hours, so the tool is deliberately cautious.

Every change is checked before it is applied

Each operation produces a new document, which is checked for structural problems — a group referring to a member that does not exist, a unit in two groups at once, a group of one, a head that is not a member, a proposition orphaned from its line. If any check fails, the change is refused and the document is left exactly as it was. You get a message and a link to report it with diagnostics attached.

This is why undo can never take you into a broken state: a refused change never enters the history.

Files are validated and repaired on open

An older or damaged .fxpa is checked as it opens. Problems that can be fixed without inventing anything are fixed — a group naming a line that has since gained propositions has that line replaced by its propositions; dangling references and duplicates are dropped. Nothing is ever deleted and no analysis is invented. If a file cannot be made sound, you are told rather than shown something that looks fine but is not.

Reporting a problem

Report a problem and Suggest a feature at the foot of the window open a pre-filled GitHub issue. The problem report includes diagnostics about the document's structure — counts, shapes, versions — below a blank space for your description. It never includes your language data.

The .fxpa file

.fxpa is plain JSON. It holds the lines (with their text, glosses, times and speakers), any propositions, and the tree of groups with their labels.

Two things are deliberately not stored, because they are derived and storing them means they can drift from the truth:

  • Whether a group is symmetrical or asymmetrical — derived from whether it has any heads.
  • The nesting level of a group — derived from where it sits in the tree.

Audio times are the opposite case and are stored: they are observed from a recording, not derivable from anything, and the tool never invents one.

Zoom, collapsed state and the help panel are per-device viewing preferences and are not part of the analysis.

Console functions

For diagnosis, in the browser console:

FunctionWhat it prints
fxTree()The group tree as it currently stands — the fastest way to see what an operation actually did.
fxBlanks()The blank lines in the document and where they are.
fxReport()The diagnostics block that a problem report would carry.

If something goes wrong, run fxTree() immediately, before any other click — that captures the state that caused it.

Troubleshooting

"I can't select those two lines together"

They are not adjacent. Selection is always one unbroken run — see Selecting and grouping. If a line is in the way, consider whether it belongs in the group, or group the whole run and then Release the edge.

"My line disappeared from the diagram"

It probably has propositions, which stand in for it. Switch on Show language-data lines that are not in the tree in the export settings.

"The collapsed-group setting looks like it does nothing"

Check the group is actually collapsed — the setting only affects collapsed groups, and an expanded document has none.

"Relation names are being cut short"

You have rotated slot labels switched on, which reserves horizontal space. Widen Indent per level, or switch slot labels to Above the relation.

"The app refused my change"

The invariant check found a structural problem in the result and kept your document as it was. That is the tool protecting your work. Use the report link — the diagnostics are what make it fixable.

"I opened an old file and things looked out of order"

Older files predate the current data model. They are repaired on open, and editing them settles the ordering. If a file still looks wrong after that, report it with fxTree() output.
